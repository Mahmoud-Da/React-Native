*** 1- Introduction ***
# 1. Overview of the Lecture

This section introduces **navigation in mobile apps**, focusing on making the app more interactive and functional.

Key idea:
Move from a static UI to a **multi-screen app** where users can:

* Switch between screens using tabs
* Open detailed views from list items (cards)
* Interact with gestures (e.g., pull-down)

---

# 2. What is Navigation?

Navigation allows users to move between different parts (screens) of an app.

### Common navigation patterns:

1. **Tab Navigation (Bottom Tabs)**
   Switch between main sections of the app.

2. **Stack Navigation**
   Move forward to a new screen (e.g., details) and go back.

3. **Gesture-based Navigation**
   Interactions like swipe or pull-down.

---

import { ScrollView, RefreshControl } from "react-native";
import React, { useState } from "react";

function ListingsScreen() {
  const [refreshing, setRefreshing] = useState(false);

  const onRefresh = () => {
    setRefreshing(true);
    // simulate reload
    setTimeout(() => setRefreshing(false), 2000);
  };

  return (
    <ScrollView
      refreshControl={
        <RefreshControl refreshing={refreshing} onRefresh={onRefresh} />
      }
    >
      {/* Content */}
    </ScrollView>
  );
}

# 9. Full Final Code

-------------------code----------------------
import React, { useState } from "react";
import { NavigationContainer } from "@react-navigation/native";
import { createBottomTabNavigator } from "@react-navigation/bottom-tabs";
import { createStackNavigator } from "@react-navigation/stack";
import { Button, ScrollView, RefreshControl, Text } from "react-native";

const Tab = createBottomTabNavigator();
const Stack = createStackNavigator();

function ListingsScreen({ navigation }) {
  const [refreshing, setRefreshing] = useState(false);

  const onRefresh = () => {
    setRefreshing(true);
    setTimeout(() => setRefreshing(false), 2000);
  };

  return (
    <ScrollView
      refreshControl={
        <RefreshControl refreshing={refreshing} onRefresh={onRefresh} />
      }
    >
      <Button
        title="Go to Details"
        onPress={() => navigation.navigate("Details")}
      />
    </ScrollView>
  );
}

function ListingDetailsScreen() {
  return <Text>Details Screen</Text>;
}

function SettingsScreen() {
  return <Text>Settings Screen</Text>;
}

function FeedNavigator() {
  return (
    <Stack.Navigator>
      <Stack.Screen name="Listings" component={ListingsScreen} />
      <Stack.Screen name="Details" component={ListingDetailsScreen} />
    </Stack.Navigator>
  );
}

function Tabs() {
  return (
    <Tab.Navigator>
      <Tab.Screen name="Feed" component={FeedNavigator} />
      <Tab.Screen name="Settings" component={SettingsScreen} />
    </Tab.Navigator>
  );
}

export default function App() {
  return (
    <NavigationContainer>
      <Tabs />
    </NavigationContainer>
  );
}
-------------------code----------------------

# 10. Important Notes & Best Practices

* Keep navigation structure **modular** (separate navigators per feature).
* Use **stack inside tabs**, not the opposite.
* Name routes clearly (e.g., `ListingDetails` instead of `Screen2`).
* Avoid deeply nested navigators unless necessary.
* Pass only required data between screens.
* Use gestures (like pull-to-refresh) to improve UX.

# 6. Types of Navigators

React Navigation provides **three main navigator types**:

---

## 6.1 Stack Navigator

Used to move between screens like a stack.

### Concept:

* Screens are stacked on top of each other
* You can:

  * **Push** a new screen
  * **Pop** back to previous screen

### Example:

-------------------code----------------------
navigation.navigate("Details");
navigation.goBack();
-------------------code----------------------

### Use case:

* Moving from a list → details screen

---

## 6.2 Tab Navigator

Used to create tabs (usually at the bottom).

### Concept:

* Each tab represents a main section
* Users can switch between them easily

### Use case:

* Home / Settings / Profile tabs

---

## 6.3 Drawer Navigator

Used to create a side menu (drawer).

### Concept:

* Slide from the left side
* Contains navigation links

### Use case:

* Apps with many sections

Note:

* Not covered in this course (left for self-study)

* Have **similar APIs**

# 2. Navigation Between Screens

React Navigation provides a **navigation prop** to screen components.

### Key idea:

* Every screen automatically receives a `navigation` object
* This object allows moving between screens

* `navigation.navigate("TweetDetails")`
  → moves user to the **TweetDetails screen**

# 4. What Happens Automatically

* A **header** is shown (Stack Navigator default)
* A **back button** appears automatically
* Navigation state is managed internally

---

# 5. Understanding the Navigation Object

The `navigation` object provides methods like:

* `navigate()` → go to a screen
* `goBack()` → go back
* `reset()` → reset navigation state

### Stack-specific methods:

* `push()` → add new screen instance
* `replace()` → replace current screen
* `pop()` → go back one screen
* `popToTop()` → go to first screen

---

# 6. navigate vs push (Important Concept)

### 6.1 navigate()

-------------------code----------------------
navigation.navigate("Tweets");
-------------------code----------------------

* Ensures **only one instance** of the screen exists
* If already on that screen → nothing happens

---

### 6.2 push()

-------------------code----------------------
navigation.push("Tweets");
-------------------code----------------------

* Always creates a **new instance**
* Stack grows (you can go back multiple times)

---

### Key Difference:

| Method   | Behavior                        |
| -------- | ------------------------------- |
| navigate | Reuses existing screen          |
| push     | Always adds new screen instance |

---

# 7. Navigation in Child Components (Problem)

The `navigation` prop is **only available in screens**:

-------------------code----------------------
<Stack.Screen name="Tweets" component={Tweets} />
-------------------code----------------------

So:

* `Tweets` → has navigation prop
* Child components inside it → DO NOT

---

*** 5- Passing Parameters to Routes ***
# 1. Overview of the Lecture

This lecture explains how to **pass data (parameters) between screens** in React Navigation.

Key ideas:

* Use `navigation.navigate()` with parameters
* Access data using the `route` prop
* Understand how data flows between screens

---

# 2. Why Passing Parameters is Important

When navigating, you often need to send data such as:

* Item ID (e.g., tweet ID)
* Full object (e.g., tweet data)

Example:

* Tap a tweet → open its details → show correct data

---

# 3. Step 1 – Pass Parameters with navigate()

The `navigate()` function accepts a second argument (an object).

### Example:

-------------------code----------------------
navigation.navigate("TweetDetails", { id: 1 });
-------------------code----------------------

### Explanation:

* First argument → screen name
* Second argument → parameters object
* You can pass:

  * Single value (`id`)
  * Multiple values (`id`, `title`, etc.)
  * Entire object

---

# 4. Step 2 – Add Button with Parameters

-------------------code----------------------
const Tweets = ({ navigation }) => (
  <Screen>
    <Button
      title="View Tweet"
      onPress={() =>
        navigation.navigate("TweetDetails", { id: 1 })
      }
    />
  </Screen>
);
-------------------code----------------------

---

# 5. Step 3 – Access Parameters in Target Screen

React Navigation provides a **route prop** to screen components.

### Example:

-------------------code----------------------
const TweetDetails = ({ route }) => {
  return (
    <Screen>
      <Text>{route.params.id}</Text>
    </Screen>
  );
};
-------------------code----------------------

### Explanation:

* `route.params` contains the object passed from previous screen
* Access values using keys (`id`, `title`, etc.)

---

# 6. How Data Flow Works

1. User taps button
2. `navigate("TweetDetails", { id: 1 })` is called
3. React Navigation passes `{ id: 1 }`
4. Target screen receives it via `route.params`

---

# 7. Step 4 – Access Params in Child Components (Advanced)

Problem:

* `route` prop is only available in **screen components**

Solution:

* Use `useRoute()` hook

-------------------code----------------------
import { useRoute } from "@react-navigation/native";

const CustomComponent = () => {
  const route = useRoute();

  return <Text>{route.params.id}</Text>;
};
-------------------code----------------------

---

-------------------code----------------------

import { Text, Button } from "react-native";
import {
  NavigationContainer,
} from "@react-navigation/native";
import { createStackNavigator } from "@react-navigation/stack";

import Screen from "./app/components/Screen";

      title="View Tweet"
      onPress={() =>

      }
    />
  </Screen>

  <Screen>
    <Text>Tweet ID: {route.params.id}</Text>
  </Screen>

*** 10- Nesting Navigators ***
# 1. Overview of the Lecture

This lecture explains **nesting navigators** in React Navigation.

Key idea:

* Combine **Tab Navigator + Stack Navigator**
* Fix navigation errors and enable deep navigation inside tabs

---

# 2. The Problem

### Current setup:

* App uses only **Tab Navigator**
* Tabs:

  * Feed → Tweets screen
  * Account → Account screen

### Issue:

When navigating:

-------------------code----------------------
navigation.navigate("TweetDetails");
-------------------code----------------------

You get error:

-------------------code----------------------
The action 'NAVIGATE' was not handled by any navigator
-------------------code----------------------

### Why?

* Tab Navigator **does not know about `TweetDetails`**
* It only knows:

  * Feed
  * Account

---

# 3. Solution – Nesting Navigators

### Concept:

Instead of:

-------------------code----------------------
<Tab.Screen name="Feed" component={Tweets} />
-------------------code----------------------

Use:

-------------------code----------------------
<Tab.Screen name="Feed" component={FeedNavigator} />
-------------------code----------------------

Where `FeedNavigator` is a **Stack Navigator**.

---

-------------------code---------------------- id="k1z9rm"
import { createStackNavigator } from "@react-navigation/stack";

  <Stack.Navigator>
    <Stack.Screen name="Tweets" component={Tweets} />
    <Stack.Screen name="TweetDetails" component={TweetDetails} />
  </Stack.Navigator>
);
-------------------code----------------------

---

# 5. Step 2 – Use Stack Inside Tab

-------------------code---------------------- id="t7m2qp"
<Tab.Screen name="Feed" component={FeedNavigator} />
-------------------code----------------------

---

# 6. Step 3 – Keep Account Tab Simple

-------------------code---------------------- id="w8f4xn"

  <Screen>
    <Text>Account</Text>
  </Screen>
);
-------------------code----------------------

---

# 7. Step 4 – Final Tab Navigator

-------------------code---------------------- id="p3c8vd"

  <Tab.Navigator>
    <Tab.Screen name="Feed" component={FeedNavigator} />
    <Tab.Screen name="Account" component={Account} />
  </Tab.Navigator>
);
-------------------code----------------------

---

# 8. Why Nesting Works

### Before:

* Tab Navigator didn’t know about `TweetDetails`

### After:

* Feed tab → uses Stack Navigator
* Stack Navigator knows:

  * Tweets
  * TweetDetails

So navigation works correctly.

Each tab has its **own navigation stack**.

### Example:

1. Go to Feed → open TweetDetails
2. Switch to Account
3. Go back to Feed

Result:

* Still on **TweetDetails** (state preserved)

  const listing = route.params;

  return (
    <Screen>
      <Text>{listing.title}</Text>
      <Text>{listing.price}</Text>
    </Screen>
  );
};

const AccountScreen = () => (
  <Screen>
    <Text>Account</Text>
  </Screen>
);

const FeedNavigator = () => (
  <Stack.Navigator>
    <Stack.Screen name="Listings" component={ListingsScreen} />
    <Stack.Screen name="ListingDetails" component={ListingDetailsScreen} />
  </Stack.Navigator>
);

const TabNavigator = () => (
  <Tab.Navigator>
    <Tab.Screen name="Feed" component={FeedNavigator} />
    <Tab.Screen name="Account" component={AccountScreen} />
  </Tab.Navigator>
);

const App = () => (
  <NavigationContainer>
    <TabNavigator />
  </NavigationContainer>
);

export default App;

*** 13- Navigation Theme ***
# 1. Overview of the Lecture

This lecture explains how to **customize the global navigation theme** in React Navigation.

Key idea:

* Override the default theme to match your app’s design
* Apply consistent colors across all screens

---

# 2. Why Use a Custom Navigation Theme?

By default:

* React Navigation uses a **gray background**
* Default colors may not match your app

Solution:

* Create a **custom theme**
* Apply your own color palette globally

---

# 3. Step 1 – Create Theme File

Create a new file:

-------------------code----------------------
app/navigation/navigationTheme.js
-------------------code----------------------

---

# 4. Step 2 – Import Default Theme

-------------------code----------------------
import { DefaultTheme } from "@react-navigation/native";
-------------------code----------------------

### Explanation:

* `DefaultTheme` is a JavaScript object
* Contains colors and styles used by navigation

---

# 5. Step 3 – Create Custom Theme

Use the **spread operator** to copy and override values.

-------------------code----------------------
import colors from "../config/colors";

const navigationTheme = {
  ...DefaultTheme,
  colors: {
    ...DefaultTheme.colors,
    primary: colors.primary,
    background: colors.white,
  },
};

export default navigationTheme;
-------------------code----------------------

---

# 6. Understanding the Code

### Step-by-step:

1. Copy entire default theme:

-------------------code----------------------
...DefaultTheme
-------------------code----------------------

2. Override only `colors`:

-------------------code----------------------
colors: { ... }
-------------------code----------------------

3. Copy existing colors:

-------------------code----------------------
...DefaultTheme.colors
-------------------code----------------------

4. Override specific values:

-------------------code----------------------
primary: colors.primary,
background: colors.white
-------------------code----------------------

---

# 7. Step 4 – Apply Theme in App.js

-------------------code----------------------
import navigationTheme from "./app/navigation/navigationTheme";
-------------------code----------------------

---

### Add to NavigationContainer:

-------------------code----------------------
<NavigationContainer theme={navigationTheme}>
-------------------code----------------------

---

# 8. Updated App.js

-------------------code----------------------

-------------------code----------------------

---

# 9. Result After Applying Theme

* Background becomes **white instead of gray**
* Primary color matches your app design
* Buttons and navigation elements use your palette

---

# 10. Important Notes & Best Practices

* Always use a centralized color file (`config/colors.js`)
* Override only what you need (don’t rewrite everything)
* Keep theme consistent across app
* Use meaningful color names (`primary`, `secondary`, etc.)
* Avoid hardcoding colors inside components
