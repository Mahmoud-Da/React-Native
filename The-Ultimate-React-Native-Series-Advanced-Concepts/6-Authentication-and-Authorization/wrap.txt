# React Native Authentication Section - Introduction

## 1. Overview

This section introduces **Authentication** in React Native applications.

Authentication allows users to:

1. Register for a new account
2. Log into an existing account
3. Access protected features
4. Maintain user identity across app sessions

By the end of this section, the application will support:

* User Registration
* User Login
* User Authentication Flow

---

# 2. Why Authentication Matters

Most real-world mobile applications require users to identify themselves before accessing certain features.

Examples:

| App Type         | Authentication Needed |
| ---------------- | --------------------- |
| E-commerce       | Yes                   |
| Social Media     | Yes                   |
| Banking          | Yes                   |
| Marketplace Apps | Yes                   |
| Messaging Apps   | Yes                   |

Authentication helps:

* Protect user data
* Associate content with users
* Restrict access to authorized users
* Provide personalized experiences

# 4. Typical Authentication Flow

### Step 1: Register

User submits:

-------------------code----------------------
{
  "name": "John",
  "email": "john@test.com",
  "password": "123456"
}
-------------------code----------------------

Server creates account.

---

### Step 2: Login

User submits:

-------------------code----------------------
{
  "email": "john@test.com",
  "password": "123456"
}
-------------------code----------------------

Server verifies credentials.

---

### Step 3: Receive Token

Server returns:

-------------------code----------------------
{
  "token": "JWT_TOKEN_HERE"
}
-------------------code----------------------

---

### Step 4: Store Authentication Token

The token is stored locally on the device.

Common storage options:

-------------------code----------------------
SecureStore (recommended)
AsyncStorage
-------------------code----------------------

---

### Step 5: Access Protected APIs

Future API requests include the token:

-------------------code----------------------http

-------------------code----------------------

Server verifies the token before returning protected data.

# 7. Important Notes

### Do Not Store Tokens in AsyncStorage

Authentication tokens are sensitive data.

Prefer:

-------------------code----------------------
expo-secure-store
-------------------code----------------------

instead of:

-------------------code----------------------
AsyncStorage
-------------------code----------------------

---

### Authentication State Should Be Global

Many screens need access to the authenticated user.

Common solutions:

-------------------code----------------------
React Context
-------------------code----------------------

or

-------------------code----------------------
Redux
-------------------code----------------------

Context is usually sufficient for most apps.

---

### Handle Login Failures Gracefully

Always provide feedback when authentication fails.

Example:

-------------------code----------------------
alert("Invalid email or password");
-------------------code----------------------

---

### Separate Authentication Logic

Keep authentication-related code inside dedicated API modules.

Example:

-------------------code----------------------
api/
 ├── auth.js
 ├── users.js
 └── client.js
-------------------code----------------------

---

# 2. Why Not Use Third-Party Authentication Services?

The instructor intentionally avoids using commercial authentication providers for two main reasons.

---

## Reason 1: Not Everyone Wants to Use Paid Services

Many developers:

* Prefer full control over their backend
* Do not want vendor lock-in
* May not want recurring costs
* May work on projects with limited budgets

Examples:

Using a custom authentication system allows the course to remain useful regardless of budget.

* Authentication workflows

Example:

-------------------code----------------------

* Course content to become outdated

# 2. Authentication Process

## Step 1: User Logs In

The user enters:

-------------------code----------------------
Email
Password
-------------------code----------------------

and submits the login form.

Example request:

-------------------code----------------------
await apiClient.post("/auth", {
  email,
  password,
});
-------------------code----------------------

---

## Step 2: Send Request to Backend

A POST request is sent to the authentication endpoint.

-------------------code----------------------http
POST /auth
-------------------code----------------------

Example:

-------------------code----------------------
{
  email: "john@test.com",
  password: "123456"
}
-------------------code----------------------

---

## Step 3: Server Validates Credentials

The backend verifies:

-------------------code----------------------
Does the user exist?
Is the password correct?
-------------------code----------------------

If validation fails:

-------------------code----------------------
{
  error: "Invalid email or password"
}
-------------------code----------------------

If validation succeeds:

-------------------code----------------------
{
  token: "LONG_AUTH_TOKEN"
}
-------------------code----------------------

---

# 3. What Is an Authentication Token?

An authentication token is similar to:

* Passport
* Driver's License
* ID Card

It proves the user's identity.

Conceptually:

-------------------code----------------------
User
  │
  ▼
Authenticates
  │
  ▼
Receives Token
  │
  ▼
Uses Token For Future Requests
-------------------code----------------------

---

## Token Characteristics

An auth token is:

-------------------code----------------------
Long string
Encrypted/Signed
Contains user information
Issued by server
-------------------code----------------------

Example:

-------------------code----------------------
"eyJhbGciOiJIUzI1NiIsInR..."
-------------------code----------------------

The actual token is much longer.

---

# 4. Extracting User Information

After receiving the token, the app can extract user data.

Typical user information:

-------------------code----------------------

  name: "John Smith",
  email: "john@test.com"

-------------------code----------------------

This data becomes the application's current user object.

# 8. The Problem with Prop Drilling

One approach would be:

-------------------code----------------------
<App user={user}>
-------------------code----------------------

then:

-------------------code----------------------
<Navigator user={user}>
-------------------code----------------------

then:

-------------------code----------------------
<Screen user={user}>
-------------------code----------------------

then:

-------------------code----------------------
<Component user={user}>
-------------------code----------------------

and so on.

---

## What Is Prop Drilling?

Prop drilling means repeatedly passing data through multiple component levels.

Example:

-------------------code----------------------
App
 │
 ▼
Navigator
 │
 ▼
Screen
 │
 ▼
Component
 │
 ▼
Child Component
-------------------code----------------------

Even components that do not need the user object must pass it down.

Problems:

* Repetitive
* Hard to maintain
* Difficult to scale
* Clutters component APIs

---

# 9. Using React Context Instead

React Context solves this problem.

---

## Create Context

-------------------code----------------------
const AuthContext = React.createContext();
-------------------code----------------------

---

## Provide User

In App.js:

-------------------code----------------------
<AuthContext.Provider value={user}>
  <AppNavigator />
</AuthContext.Provider>
-------------------code----------------------

---

## Consume User Anywhere

Any component can access:

-------------------code----------------------
const user = useContext(AuthContext);
-------------------code----------------------

without passing props manually.

---

## Benefits

-------------------code----------------------
No prop drilling
Cleaner code
Easier maintenance
Simple implementation
-------------------code----------------------

---

# 10. Does React Context Replace Redux?

No.

They solve different problems.

---

## React Context Is Good For

Small objects:

-------------------code----------------------
{
  id: 1,
  name: "John"
}
-------------------code----------------------

Examples:

* Authenticated user
* Theme settings
* Language settings
* App configuration

Characteristics:

-------------------code----------------------
Small data
Changes infrequently
Simple sharing
-------------------code----------------------

---

## Redux Is Better For

Large application state.

Examples:

-------------------code----------------------
Shopping carts
Messaging systems
Complex dashboards
Large shared state
-------------------code----------------------

Characteristics:

-------------------code----------------------
Large state tree
Frequent updates
Many subscribers
Complex data flow
-------------------code----------------------

---

# 11. Why Redux Performs Better for Large State

With Context:

-------------------code----------------------
State changes
      │
      ▼
Entire component tree re-renders
-------------------code----------------------

Even components that don't use the changed property may re-render.

---

With Redux:

-------------------code----------------------
State changes
      │
      ▼
Only subscribed components re-render
-------------------code----------------------

This makes Redux more efficient for large, frequently-changing state.

Only use Redux when:

-------------------code----------------------

The authenticated user should generally be stored in:

-------------------code----------------------

-------------------code----------------------

or a dedicated authentication provider.

This allows navigation and other components to react to authentication changes.

# Full Authentication Flow Example

-------------------code----------------------
const [user, setUser] = useState(null);

const handleLogin = async (credentials) => {
  const token = await authApi.login(credentials);

  const user = decodeToken(token);

  setUser(user);
};

return (
  <AuthContext.Provider value={user}>
    {user ? <AppNavigator /> : <AuthNavigator />}
  </AuthContext.Provider>
);
-------------------code----------------------

# Summary

This lecture explains how authentication works at the application architecture level.

Key concepts:

1. User submits email and password.
2. App sends a POST request to `/auth`.
3. Server validates credentials.
4. Server returns an authentication token.
5. User information is extracted from the token.
6. The user object is stored in app state.
7. Navigation is determined by whether the user exists.
8. React Context is used to share user data throughout the application.
9. Prop drilling should be avoided.
10. Redux is useful only for large, frequently changing shared state, while React Context is ideal for authentication data.
