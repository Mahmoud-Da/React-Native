*** 1- Introduction ***
# Offline Support in React Native Apps

## 1. Overview

This section introduces **offline-first mobile app development**.

The goal is to improve the user experience when internet connectivity is unavailable or unstable.

### Features to Implement

1. Detect when the device is offline.
2. Show an offline notification banner.
3. Load listings from local cache when no internet connection is available.
4. Continue providing access to previously loaded data.

This makes the application more reliable and production-ready.

---

# 2. Why Offline Support Matters

Internet access is not always:

* Available
* Stable
* Fast
* Reliable

Without offline support:

* API requests fail.
* Users see empty screens.
* The app becomes unusable.

With offline support:

* Users can still browse cached content.
* The app feels faster and more professional.
* Temporary network issues do not break the experience.

---

*** 2- Strategies for Building Offline Capable Apps ***
# Offline-Capable Apps: Common Strategies

## 1. Overview

Building an offline-capable app means designing your application to continue providing a good user experience even when internet connectivity is unavailable or unreliable.

In this lecture, four common offline strategies are introduced.

As the functionality becomes more advanced, the implementation complexity and development cost increase.

---

# 2. The Four Offline Strategies

## Strategy 1: Notify the User

The simplest approach is to inform users that they are offline.

### Example

-------------------code----------------------
No Internet Connection
Please check your network settings.
-------------------code----------------------

### Benefits

* Easy to implement
* Improves user experience
* Prevents confusion

### Typical Usage

-------------------code----------------------
<OfflineNotice />
-------------------code----------------------

### Flow

-------------------code----------------------
Internet Lost
      ↓
Show Offline Message
      ↓
User Understands Problem
-------------------code----------------------

---

## Strategy 2: Disable Certain Features

When internet access is unavailable, some features can be temporarily disabled.

### Examples

Features that may require internet:

* Posting listings
* Uploading images
* Sending messages
* Making purchases

### Example

-------------------code----------------------
<Button disabled={!isConnected} title="Post Listing" />
-------------------code----------------------

### Flow

-------------------code----------------------
Device Offline
      ↓
Disable Online Features
      ↓
Prevent Failed Requests
-------------------code----------------------

### Benefits

* Prevents unnecessary errors
* Creates predictable behavior
* Improves usability

---

## Strategy 3: Cache Data Locally

A more advanced approach is to store data locally so users can still access it offline.

### Example

Store:

-------------------code----------------------
Listings
User Profiles
Settings
Product Catalogs
-------------------code----------------------

### Flow

-------------------code----------------------
Online
   ↓
Download Data
   ↓
Save To Cache
   ↓
Offline
   ↓
Load Cached Data
-------------------code----------------------

### Benefits

* Faster loading
* Better user experience
* App remains usable offline

### Example

-------------------code----------------------
const listings = await getCachedListings();
-------------------code----------------------

---

## Strategy 4: Queue User Actions

This is the most advanced strategy.

If users perform actions while offline, the app stores those actions locally and executes them later when internet connectivity returns.

### Example

User submits a listing while offline:

-------------------code----------------------
Post Listing
-------------------code----------------------

Instead of failing:

-------------------code----------------------
Store Request Locally
-------------------code----------------------

When internet returns:

-------------------code----------------------
Upload Request Automatically
-------------------code----------------------

### Flow

-------------------code----------------------
User Creates Listing
         ↓
Internet Unavailable
         ↓
Store Action Locally
         ↓
Connection Restored
         ↓
Send Action To Server
-------------------code----------------------

### Examples

Common applications that use this strategy:

* Email clients
* Messaging apps
* Note-taking apps
* Task management apps

---

# 3. Comparing the Strategies

1. Notify users when internet is unavailable.
2. Disable features that require network access.

*** 3- Detecting Network Status ***
# Detecting Network Connectivity with NetInfo

## 1. Overview

Before implementing offline support, we need a way to determine whether the device has internet access.

React Native and Expo provide a popular library called **NetInfo**, built by the React Native community, for monitoring network status.

With NetInfo, we can:

* Detect network connectivity
* Determine if internet access is actually available
* Show offline notifications
* Disable online-only features
* React to network status changes in real time

---

# 2. Installing NetInfo

Install the NetInfo package in your Expo project.

-------------------code----------------------
expo install @react-native-community/netinfo
-------------------code----------------------

After installation, import it into your application.

-------------------code----------------------
import NetInfo from "@react-native-community/netinfo";
-------------------code----------------------

---

# 3. Getting Network Status Once with fetch()

## Purpose

Retrieve network information a single time.

### Example

-------------------code----------------------
NetInfo.fetch().then((netInfo) => {
  console.log(netInfo);
});
-------------------code----------------------

---

## Returned Object

NetInfo returns an object containing information about the current network state.

Example structure:

-------------------code----------------------
{
  isConnected: true,
  isInternetReachable: true,
  details: {
    ipAddress: "...",
    subnet: "...",
    ssid: "...",
  }
}
-------------------code----------------------

---

# 4. Understanding Important Properties

## isConnected

Indicates whether a network connection exists.

-------------------code----------------------
netInfo.isConnected
-------------------code----------------------

Example:

-------------------code----------------------
true
-------------------code----------------------

This means:

-------------------code----------------------text
Device connected to Wi-Fi or Mobile Network
-------------------code----------------------

---

## isInternetReachable

Indicates whether the internet is actually accessible.

-------------------code----------------------
netInfo.isInternetReachable
-------------------code----------------------

Example:

-------------------code----------------------
true
-------------------code----------------------

This means:

-------------------code----------------------text
Internet access confirmed
-------------------code----------------------

---

# 5. Why isInternetReachable Is Better

Many developers only check:

-------------------code----------------------
netInfo.isConnected
-------------------code----------------------

This is not enough.

### Example Problem

-------------------code----------------------text
Connected to Wi-Fi
       ↓
Router has no internet
       ↓
isConnected = true
       ↓
Internet unavailable
-------------------code----------------------

Your app incorrectly assumes internet exists.

---

### Better Approach

Always check:

-------------------code----------------------
netInfo.isInternetReachable
-------------------code----------------------

This verifies actual internet availability.

---

# 6. Why isInternetReachable Starts as null

When NetInfo starts:

-------------------code----------------------
isInternetReachable = null
-------------------code----------------------

Reason:

-------------------code----------------------text
NetInfo is testing connectivity
-------------------code----------------------

Internally it:

1. Contacts a remote server
2. Waits for a response
3. Determines internet availability

Example flow:

-------------------code----------------------text
App Starts
     ↓
isInternetReachable = null
     ↓
Connectivity Test
     ↓
true / false
-------------------code----------------------

---

# 7. Monitoring Network Changes

Using `fetch()` only checks once.

For real applications, we usually monitor changes continuously.

---

## Using addEventListener()

-------------------code----------------------
const unsubscribe = NetInfo.addEventListener((netInfo) => {
  console.log(netInfo);
});
-------------------code----------------------

This callback runs every time the network status changes.

---

### Example

-------------------code----------------------text
Wi-Fi Connected
      ↓
Callback Executes

Wi-Fi Disconnected
      ↓
Callback Executes

Mobile Data Enabled
      ↓
Callback Executes
-------------------code----------------------

---

# 8. Unsubscribing Is Important

`addEventListener()` returns a function.

-------------------code----------------------
const unsubscribe = NetInfo.addEventListener(...);
-------------------code----------------------

Use it when the component is removed.

-------------------code----------------------
unsubscribe();
-------------------code----------------------

---

## Why?

Without cleanup:

-------------------code----------------------text
Component Removed
       ↓
Listener Still Running
       ↓
Memory Leak
-------------------code----------------------

This wastes resources and may cause bugs.

---

# 9. Traditional Class Component Approach

### Subscribe

-------------------code----------------------
componentDidMount() {
  this.unsubscribe = NetInfo.addEventListener(
    (netInfo) => {
      console.log(netInfo);
    }
  );
}
-------------------code----------------------

---

### Unsubscribe

-------------------code----------------------
componentWillUnmount() {
  this.unsubscribe();
}
-------------------code----------------------

---

# 10. Using the useNetInfo Hook

In React Native function components, we typically use a hook instead.

Import:

-------------------code----------------------
import { useNetInfo } from "@react-native-community/netinfo";
-------------------code----------------------

---

## Usage

-------------------code----------------------
const netInfo = useNetInfo();
-------------------code----------------------

---

## Benefits

The hook automatically handles:

* Subscription
* Updates
* Cleanup
* Unsubscription

No manual listener management required.

---

# 11. Example: Display Different UI

Render content conditionally.

return netInfo.isInternetReachable ? (
  <OnlineView />

# Full Final Code

-------------------code----------------------
import React from "react";
import { View, Text, Button } from "react-native";
import { useNetInfo } from "@react-native-community/netinfo";

function App() {
  const netInfo = useNetInfo();

  return (
    <View>
      {!netInfo.isInternetReachable && (
        <Text>No Internet Connection</Text>
      )}

      <Button
        title="Upload"
        disabled={!netInfo.isInternetReachable}
      />
    </View>
  );
}

export default App;
-------------------code----------------------

Prefer:

-------------------code----------------------

-------------------code----------------------

-------------------code----------------------

-------------------code----------------------

because a device may be connected to a network without having internet access.

## Handle null Values

Initially:

-------------------code----------------------

-------------------code----------------------

---

## Clean Up Listeners

If using:

-------------------code----------------------

* Subscribing
