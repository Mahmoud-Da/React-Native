*** 1- Introduction ***
# Offline Support in React Native Apps

## 1. Overview

This section introduces **offline-first mobile app development**.

The goal is to improve the user experience when internet connectivity is unavailable or unstable.

### Features to Implement

1. Detect when the device is offline.
2. Show an offline notification banner.
3. Load listings from local cache when no internet connection is available.
4. Continue providing access to previously loaded data.

This makes the application more reliable and production-ready.

---

# 2. Why Offline Support Matters

Internet access is not always:

* Available
* Stable
* Fast
* Reliable

Without offline support:

* API requests fail.
* Users see empty screens.
* The app becomes unusable.

With offline support:

* Users can still browse cached content.
* The app feels faster and more professional.
* Temporary network issues do not break the experience.

# Offline-Capable Apps: Common Strategies

## 1. Overview

Building an offline-capable app means designing your application to continue providing a good user experience even when internet connectivity is unavailable or unreliable.

In this lecture, four common offline strategies are introduced.

As the functionality becomes more advanced, the implementation complexity and development cost increase.

---

# 2. The Four Offline Strategies

## Strategy 1: Notify the User

The simplest approach is to inform users that they are offline.

### Example

-------------------code----------------------

Please check your network settings.
-------------------code----------------------

### Benefits

* Easy to implement
* Improves user experience
* Prevents confusion

-------------------code----------------------

-------------------code----------------------

-------------------code----------------------

      ↓

      ↓

* Posting listings
* Uploading images
* Sending messages
* Making purchases

### Example

-------------------code----------------------

-------------------code----------------------

### Flow

-------------------code----------------------

      ↓
Disable Online Features
      ↓
Prevent Failed Requests
-------------------code----------------------

### Benefits

* Prevents unnecessary errors
* Creates predictable behavior
* Improves usability

---

## Strategy 3: Cache Data Locally

A more advanced approach is to store data locally so users can still access it offline.

### Example

-------------------code----------------------

User Profiles
Settings
Product Catalogs
-------------------code----------------------

### Flow

-------------------code----------------------
Online
   ↓
Download Data
   ↓
Save To Cache
   ↓
Offline
   ↓

-------------------code----------------------

### Benefits

* Faster loading
* Better user experience
* App remains usable offline

### Example

-------------------code----------------------

-------------------code----------------------

---

## Strategy 4: Queue User Actions

This is the most advanced strategy.

If users perform actions while offline, the app stores those actions locally and executes them later when internet connectivity returns.

### Example

User submits a listing while offline:

-------------------code----------------------

-------------------code----------------------

Instead of failing:

-------------------code----------------------

-------------------code----------------------

When internet returns:

-------------------code----------------------

-------------------code----------------------

### Flow

-------------------code----------------------
User Creates Listing
         ↓
Internet Unavailable
         ↓
Store Action Locally
         ↓
Connection Restored
         ↓
Send Action To Server
-------------------code----------------------

### Examples

Common applications that use this strategy:

* Email clients
* Messaging apps
* Note-taking apps
* Task management apps

# Detecting Network Connectivity with NetInfo

## 1. Overview

Before implementing offline support, we need a way to determine whether the device has internet access.

React Native and Expo provide a popular library called **NetInfo**, built by the React Native community, for monitoring network status.

With NetInfo, we can:

* Detect network connectivity
* Determine if internet access is actually available
* Show offline notifications
* Disable online-only features
* React to network status changes in real time

---

# 2. Installing NetInfo

Install the NetInfo package in your Expo project.

-------------------code----------------------
expo install @react-native-community/netinfo
-------------------code----------------------

After installation, import it into your application.

-------------------code----------------------
import NetInfo from "@react-native-community/netinfo";
-------------------code----------------------

---

# 3. Getting Network Status Once with fetch()

## Purpose

Retrieve network information a single time.

### Example

-------------------code----------------------
NetInfo.fetch().then((netInfo) => {
  console.log(netInfo);
});
-------------------code----------------------

---

## Returned Object

NetInfo returns an object containing information about the current network state.

Example structure:

-------------------code----------------------
{
  isConnected: true,
  isInternetReachable: true,
  details: {
    ipAddress: "...",
    subnet: "...",
    ssid: "...",
  }
}
-------------------code----------------------

---

# 4. Understanding Important Properties

## isConnected

Indicates whether a network connection exists.

-------------------code----------------------

-------------------code----------------------

Example:

-------------------code----------------------
true
-------------------code----------------------

This means:

-------------------code----------------------text
Device connected to Wi-Fi or Mobile Network
-------------------code----------------------

---

## isInternetReachable

Indicates whether the internet is actually accessible.

-------------------code----------------------
netInfo.isInternetReachable
-------------------code----------------------

Example:

-------------------code----------------------
true
-------------------code----------------------

This means:

-------------------code----------------------text
Internet access confirmed
-------------------code----------------------

---

# 5. Why isInternetReachable Is Better

Many developers only check:

-------------------code----------------------
netInfo.isConnected
-------------------code----------------------

This is not enough.

### Example Problem

-------------------code----------------------text
Connected to Wi-Fi
       ↓
Router has no internet
       ↓
isConnected = true
       ↓
Internet unavailable
-------------------code----------------------

Your app incorrectly assumes internet exists.

---

### Better Approach

Always check:

-------------------code----------------------
netInfo.isInternetReachable
-------------------code----------------------

This verifies actual internet availability.

---

# 6. Why isInternetReachable Starts as null

When NetInfo starts:

-------------------code----------------------
isInternetReachable = null
-------------------code----------------------

Reason:

-------------------code----------------------text
NetInfo is testing connectivity
-------------------code----------------------

Internally it:

1. Contacts a remote server
2. Waits for a response
3. Determines internet availability

Example flow:

-------------------code----------------------text
App Starts
     ↓
isInternetReachable = null
     ↓
Connectivity Test
     ↓
true / false
-------------------code----------------------

---

# 7. Monitoring Network Changes

Using `fetch()` only checks once.

For real applications, we usually monitor changes continuously.

---

## Using addEventListener()

-------------------code----------------------
const unsubscribe = NetInfo.addEventListener((netInfo) => {
  console.log(netInfo);
});
-------------------code----------------------

This callback runs every time the network status changes.

---

### Example

-------------------code----------------------text
Wi-Fi Connected
      ↓
Callback Executes

Wi-Fi Disconnected
      ↓
Callback Executes

Mobile Data Enabled
      ↓
Callback Executes
-------------------code----------------------

---

# 8. Unsubscribing Is Important

`addEventListener()` returns a function.

-------------------code----------------------
const unsubscribe = NetInfo.addEventListener(...);
-------------------code----------------------

Use it when the component is removed.

-------------------code----------------------
unsubscribe();
-------------------code----------------------

---

## Why?

Without cleanup:

-------------------code----------------------text
Component Removed
       ↓
Listener Still Running
       ↓
Memory Leak
-------------------code----------------------

This wastes resources and may cause bugs.

---

# 9. Traditional Class Component Approach

### Subscribe

-------------------code----------------------

  this.unsubscribe = NetInfo.addEventListener(
    (netInfo) => {
      console.log(netInfo);
    }
  );
}
-------------------code----------------------

---

### Unsubscribe

-------------------code----------------------
componentWillUnmount() {
  this.unsubscribe();
}
-------------------code----------------------

*** 4- Caching ***
# Offline Support in React Native – Caching Data

## 1. Why Caching Matters

When an app retrieves data from a server, it may be useful to store that data locally on the device.

Benefits:

* Users can still access previously loaded data when offline.
* Reduces unnecessary network requests.
* Improves app responsiveness and user experience.
* Helps build offline-capable applications.

Example:

-------------------code----------------------
Online:
Server → App → Display Listings

Offline:
Local Cache → App → Display Listings
-------------------code----------------------

---

# 2. Caching Storage Options

The lecture introduces three common storage solutions.

## Option 1: Async Storage

### What It Is

Async Storage is similar to Local Storage in web browsers.

It stores:

-------------------code----------------------
key -> value
-------------------code----------------------

where values are stored as strings.

### Characteristics

* Stores key-value pairs
* Data persists between app restarts
* Data is not encrypted
* Suitable for caching API responses
* Default storage limit is approximately 6 MB

### Good For

* API response caching
* User preferences
* App settings
* Small datasets

### Not Good For

* Passwords
* Authentication tokens
* Sensitive personal information

### Example

-------------------code----------------------
await AsyncStorage.setItem("listings", JSON.stringify(listings));

const data = await AsyncStorage.getItem("listings");

const listings = JSON.parse(data);
-------------------code----------------------

---

# 3. Option 2: Secure Store

## What It Is

Secure Store is provided by Expo and is designed for storing sensitive data securely.

### Characteristics

* Data is encrypted
* Works in Expo projects
* Available in managed and bare workflows
* Storage limit is approximately 2 MB

### Good For

* Access tokens
* Refresh tokens
* Sensitive credentials
* Authentication information

### Not Good For

* Large API response datasets
* Image caches
* Large collections of records

### Example

-------------------code----------------------
import * as SecureStore from "expo-secure-store";

await SecureStore.setItemAsync("token", token);

const token = await SecureStore.getItemAsync("token");
-------------------code----------------------

---

# 4. Option 3: SQLite

## What It Is

SQLite is a lightweight relational database that runs directly on the device.

Instead of simple key-value pairs, it allows:

* Tables
* Relationships
* SQL queries

### Characteristics

* Full database support
* Query data using SQL
* Suitable for complex offline applications

### Good For

* Large datasets
* Complex searches
* Filtering
* Relational data

### Example

-------------------code----------------------
SELECT * FROM listings
WHERE price > 100;
-------------------code----------------------

### Example Use Cases

* Messaging apps
* Inventory systems
* Offline business applications
* Large data-driven apps

---

# 5. Storage Comparison

| Feature                 | Async Storage | Secure Store | SQLite      |
| ----------------------- | ------------- | ------------ | ----------- |
| Key-Value Storage       | Yes           | Yes          | No          |
| Encrypted               | No            | Yes          | Depends     |
| Supports SQL Queries    | No            | No           | Yes         |
| Good for API Cache      | Yes           | No           | Yes         |
| Good for Sensitive Data | No            | Yes          | Sometimes   |
| Storage Limit           | ~6 MB         | ~2 MB        | Much Larger |
| Complexity              | Low           | Low          | Medium      |

---

# 6. Data Persistence

All three solutions share an important characteristic.

Data remains available after:

* Closing the app

* Device restarts

Example:

-------------------code----------------------

↓

↓

↓

↓

# 7. Important Limitation

Local storage data is removed when the application is uninstalled.

-------------------code----------------------

    ↓

    ↓

    ↓
All Local Data Removed
-------------------code----------------------

This applies to:

* Async Storage
* Secure Store
* SQLite

---

# 8. Choosing the Right Storage

### Use Async Storage When

* Caching API responses
* Storing app settings
* Saving small non-sensitive data

### Use Secure Store When

* Saving tokens
* Saving passwords
* Storing sensitive information

### Use SQLite When

* Working with large datasets
* Performing searches and filtering
* Building advanced offline apps

Avoid:

Prefer:

-------------------code----------------------

-------------------code----------------------

---

### Choose the Simplest Solution

Do not automatically use SQLite.

Ask:

* Key-value storage

# Async Storage in React Native

## 1. What is Async Storage?

Async Storage is a simple persistent storage solution for React Native applications.

It allows you to:

* Save data locally on the device
* Retrieve data later
* Keep data available after app restarts
* Cache API responses
* Store application settings

### Important Note

Async Storage was originally part of React Native Core.

However:

* It has been deprecated from React Native Core.
* It is now maintained as a separate community package.
* At the time of this lecture, Expo was still using the older React Native Core version.

Because Expo changes over time, always check the latest documentation before implementing Async Storage.

---

# 2. Importing Async Storage

At the time of the lecture:

-------------------code----------------------
import { AsyncStorage } from "react-native";
-------------------code----------------------

In modern React Native projects, the import is usually:

-------------------code----------------------
import AsyncStorage from "@react-native-async-storage/async-storage";
-------------------code----------------------

Always verify the current installation instructions.

---

# 3. Storing Data in Async Storage

## Step 1: Create an Object

-------------------code----------------------
const person = {
  id: 1,
};
-------------------code----------------------

---

## Step 2: Convert the Object to a String

Async Storage can only store strings.

Before saving an object:

-------------------code----------------------
JSON.stringify(person);
-------------------code----------------------

Example:

-------------------code----------------------
const value = JSON.stringify(person);
-------------------code----------------------

---

## Step 3: Save the Data

Use:

-------------------code----------------------
AsyncStorage.setItem(key, value);
-------------------code----------------------

Example:

-------------------code----------------------
await AsyncStorage.setItem(
  "person",
  JSON.stringify(person)
);
-------------------code----------------------

---

# 4. Why Use a Try-Catch Block?

Saving data may fail.

Possible reasons:

* Storage is unavailable
* Storage is full
* Device issues
* Unexpected system errors

Always wrap storage operations in a try-catch block.

Example:

-------------------code----------------------
try {
  await AsyncStorage.setItem(
    "person",
    JSON.stringify(person)
  );
} catch (error) {
  console.log(error);
}
-------------------code----------------------

---

# 5. Reading Data from Async Storage

## Step 1: Retrieve the Stored Value

Use:

-------------------code----------------------
AsyncStorage.getItem(key);
-------------------code----------------------

Example:

-------------------code----------------------
const value = await AsyncStorage.getItem("person");
-------------------code----------------------

The returned value is:

-------------------code----------------------
"{"id":1}"
-------------------code----------------------

# Important Notes & Best Practices

## Always Serialize Objects

Wrong:

-------------------code----------------------
await AsyncStorage.setItem("person", person);
-------------------code----------------------

Correct:

-------------------code----------------------
await AsyncStorage.setItem(
  "person",
  JSON.stringify(person)
);
-------------------code----------------------

---

## Always Parse Retrieved Objects

Wrong:

-------------------code----------------------
const person = await AsyncStorage.getItem("person");
-------------------code----------------------

Correct:

-------------------code----------------------
const person = JSON.parse(
  await AsyncStorage.getItem("person")
);
-------------------code----------------------

---

## Always Handle Errors

Wrong:

-------------------code----------------------
await AsyncStorage.setItem("person", value);
-------------------code----------------------

Correct:

-------------------code----------------------
try {
  await AsyncStorage.setItem("person", value);
} catch (error) {
  console.log(error);
}
-------------------code----------------------

---

## Do Not Store Sensitive Information

Avoid storing:

* Passwords
* Authentication tokens
* Credit card information

Use Secure Store instead.

# Summary

## What is Async Storage?

Async Storage is a local storage solution for React Native that allows applications to store data on the device.

## Key Concepts

1. Async Storage stores strings.
2. Use `JSON.stringify()` before saving objects.
3. Use `JSON.parse()` after retrieving objects.
4. Storage operations are asynchronous and return promises.
5. Always use `try-catch` for error handling.

## Main Methods

-------------------code----------------------
setItem()
getItem()
removeItem()
clear()
-------------------code----------------------

## Best Practice

For API caching and app settings, Async Storage is usually the simplest and most effective local storage solution. Always serialize objects properly and never store sensitive information in Async Storage.
