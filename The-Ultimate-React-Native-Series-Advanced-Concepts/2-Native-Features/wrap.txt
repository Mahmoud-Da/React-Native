# Accessing Native Device Features in React Native — Overview

## 1. Introduction

This lecture provides an **overview of how React Native applications access native device features**.

Modern mobile apps often rely on device capabilities such as:

* Camera
* Contacts
* Location
* Calendar
* Media library

However, these features are **not fully included in the core React Native framework**. Instead, developers typically rely on **third-party libraries or tools like Expo** to access them.

---

# 2. Native Features in Core React Native

React Native includes a **small set of built-in APIs** under its Core APIs section.

These APIs provide limited access to device functionality.

Examples include:

* Displaying alerts
* Handling the soft keyboard
* Basic platform interactions

Example of a simple alert:

-------------------code----------------------
import { Alert } from "react-native";

Alert.alert("Hello", "This is an alert message");
-------------------code----------------------

Although useful, these APIs **do not provide access to most device hardware features**.

For more advanced capabilities, additional libraries are required.

---

# 3. Third-Party Libraries for Native Features

Most device features such as:

* Camera
* Contacts
* Location services
* Image selection

are provided through **third-party React Native libraries**.

One common example is the **Image Picker library**.

This library allows developers to:

* Select images from the device gallery
* Capture photos using the device camera

Example library:

-------------------code----------------------
react-native-image-picker
-------------------code----------------------

These libraries extend React Native by providing **access to native platform functionality**.

---

# 4. Additional Setup for Native Libraries

Many third-party libraries require **extra configuration in native projects**.

Typical installation steps include:

1. Installing the library using npm or yarn

Example:

-------------------code----------------------
npm install library-name
-------------------code----------------------

or

-------------------code----------------------
yarn add library-name
-------------------code----------------------

2. Running platform-specific setup

For example, iOS projects may require commands such as:

-------------------code----------------------
cd ios
pod install
-------------------code----------------------

Because these steps involve modifying **native Android or iOS code**, they are not always compatible with certain development environments.

---

# 5. Limitations When Using Expo

When using **Expo**, developers typically **do not have direct access to native iOS or Android project files**.

Because of this limitation:

* Some third-party libraries cannot be used directly in Expo.
* Libraries requiring native setup will not work unless additional steps are taken.

---

# 6. Options When Using Expo

Developers using Expo have two main options.

## Option 1: Eject from Expo

Ejecting converts an Expo project into a **full React Native project**.

Benefits:

* Full access to native Android and iOS code
* Ability to install any React Native library

Drawbacks:

* More complex setup
* Loss of some Expo conveniences

---

## Option 2: Use Expo APIs

Expo provides its own **collection of APIs that wrap native device functionality**.

These APIs are designed to work **without requiring native configuration**.

Advantages include:

* Simple installation
* No manual native setup
* Excellent documentation
* Faster development workflow

Because of these benefits, the instructor prefers continuing with **Expo APIs whenever possible**.

# 4. Problem: No Lifecycle Methods in Functions

Function components **do NOT have**:

* componentDidMount
* componentDidUpdate
* componentWillUnmount

# 5. Solution: useEffect Hook

React introduced something called **Hooks**.

The most important one here is:

### useEffect

---

# 6. Basic useEffect

-------------------code----------------------
import { useEffect } from "react";

useEffect(() => {
  console.log("This runs after render");
});
-------------------code----------------------

But this runs **every time the component renders**.

---

# 7. Making useEffect behave like componentDidMount

## 7.1 The Trick: Dependency Array

-------------------code----------------------
useEffect(() => {
  console.log("Runs only once");
}, []);
-------------------code----------------------

---

## 7.2 Why does this work?

The second argument:

-------------------code----------------------
[]
-------------------code----------------------

is called the **dependency array**.

Meaning:

* "Run this only when dependencies change"

But:

* There are no dependencies

So:

* It runs **only once**

---

# 8. Side-by-Side Comparison

## Class Component

-------------------code----------------------
componentDidMount() {
  console.log("Runs once");
}
-------------------code----------------------

## Function Component

-------------------code----------------------
useEffect(() => {
  console.log("Runs once");
}, []);
-------------------code----------------------

They do the **same thing**.

---

# 9. Simple Mental Model

Think like this:

* Class → componentDidMount → run once
* Function → useEffect + [] → run once

# 10. Why We Use This for Permissions

In your app, you wrote:

-------------------code----------------------

  requestPermission();
}, []);
-------------------code----------------------

This means:

* When the screen loads for the first time
* Ask the user for permission
* Do not ask again on every render

* Run every time the component re-renders

This is wrong behavior.

# 5. Requesting Permission

## 5.1 The Permission Method

We use:

-------------------code----------------------
ImagePicker.requestCameraRollPermissionsAsync()
-------------------code----------------------

This is an **async function** that returns a result object.

---

## 5.2 Problem with Async in useEffect

Incorrect approach:

-------------------code----------------------
useEffect(async () => {
  const result = await ImagePicker.requestCameraRollPermissionsAsync();
}, []);
-------------------code----------------------

Problem:

* `useEffect` cannot accept an async function
* Async functions return a Promise
* `useEffect` expects a cleanup function, not a Promise

---

# 6. Correct Solution: Separate Async Function

## 6.1 Step 1 — Create Async Function

-------------------code----------------------
const requestPermission = async () => {
  const result = await ImagePicker.requestCameraRollPermissionsAsync();
};
-------------------code----------------------

---

## 6.2 Step 2 — Call Function Inside useEffect

-------------------code----------------------
useEffect(() => {
  requestPermission();
}, []);
-------------------code----------------------

Important:

* Do NOT use `await` inside `useEffect`
* Do NOT make `useEffect` async

---

# 7. Handling the Permission Response

## 7.1 Response Object

The result contains properties such as:

* `granted` (boolean)
* `status`
* `canAskAgain`
* `expires`

---

## 7.2 Using Object Destructuring

Instead of:

-------------------code----------------------
const result = await ImagePicker.requestCameraRollPermissionsAsync();

if (!result.granted) {
  alert("Permission required");
}
-------------------code----------------------

Use:

-------------------code----------------------
const { granted } = await ImagePicker.requestCameraRollPermissionsAsync();

if (!granted) {
  alert("You need to enable permission to access the library.");
}
-------------------code----------------------

Cleaner and more readable.

---

# 8. Full Step-by-Step Implementation

## Step 1 — Import Dependencies

-------------------code----------------------

import Screen from "./app/components/Screen";
-------------------code----------------------

---

## Step 2 — Create Permission Function

-------------------code----------------------

  const { granted } = await ImagePicker.requestCameraRollPermissionsAsync();

  if (!granted) {
    alert("You need to enable permission to access the library.");
  }
};
-------------------code----------------------

---

## Step 3 — Call It Once Using useEffect

-------------------code----------------------

-------------------code----------------------

---

## Step 4 — Render App

-------------------code----------------------

-------------------code----------------------

---

# 9. Full Final Code

-------------------code----------------------
import { useEffect } from "react";
import * as ImagePicker from "expo-image-picker";
import Screen from "./app/components/Screen";

export default function App() {
  const requestPermission = async () => {
    const { granted } = await ImagePicker.requestCameraRollPermissionsAsync();

    if (!granted) {
      alert("You need to enable permission to access the library.");
    }
  };

  useEffect(() => {
    requestPermission();
  }, []);

  return <Screen />;
}
-------------------code----------------------

---

# 10. How Permission Behavior Works

## First Run

* App asks for permission
* User sees system dialog
* User chooses Allow or Deny

## After First Decision

* Device remembers the choice
* No dialog appears again
* Permission result is returned immediately

---

## If Permission Is Denied

* App should show a message
* User must manually enable permission in device settings

Example (iPhone):

* Settings → App → Photos → Enable access

---

# 11. Important Notes and Best Practices

## 11.1 Never Make useEffect Async

Incorrect:

-------------------code----------------------
useEffect(async () => {})
-------------------code----------------------

Correct:

* Use a separate async function

---

## 11.2 Always Use Dependency Array

-------------------code----------------------
useEffect(() => {}, []);
-------------------code----------------------

Prevents repeated execution.

---

## 11.3 Handle Permission Denial Gracefully

* Always check `granted`
* Show clear message to the user
* Do not crash or block the app

---

## 11.4 Keep Logic Clean

* Use destructuring for cleaner code
* Separate logic into functions

---

## 12. Summary

* Permissions are required to access sensitive device features
* `useEffect` is used to run code when the component mounts
* An empty dependency array ensures the effect runs only once
* Async functions cannot be used directly inside `useEffect`
* The correct approach is to define an async function and call it inside `useEffect`
* The permission result includes a `granted` boolean
* If permission is denied, the app should notify the user
* Once permission is decided, the system remembers it and does not prompt again

This pattern is essential and will be reused for other features such as:

* Camera access

# 10. Full Final Code

-------------------code----------------------
import { useEffect } from "react";
import * as Permissions from "expo-permissions";
import Screen from "./app/components/Screen";

export default function App() {
  const requestPermission = async () => {
    const { granted } = await Permissions.askAsync(Permissions.CAMERA_ROLL);

    if (!granted) {
      alert("You need to enable permission to access the library.");
    }
  };

  useEffect(() => {
    requestPermission();
  }, []);

  return <Screen />;
}

# 12. Summary

* The Permissions API allows requesting **one or multiple permissions**
* It is installed using `expo-permissions`
* Use `Permissions.askAsync()` to request access
* It returns a result object with a `granted` boolean
* If any permission is denied, `granted` becomes false
* This approach is similar to ImagePicker’s request method
* In practice, simpler methods are often preferred unless multiple permissions are needed
