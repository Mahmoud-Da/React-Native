*** 2- Adding Chevrons ***
# Improving the ListItem Component (Adding a Chevron Icon)

## 1. Goal of This Lecture

Enhance the existing `ListItem` component by:

1. Adding a chevron icon on the right side.
2. Properly aligning the icon.
3. Improving layout using Flexbox.
4. Applying better styling practices.

This simulates a small but realistic UI improvement in a production app.

---

# 2. Step 1 – Import MaterialCommunityIcons

We need to import `MaterialCommunityIcons` from Expo vector icons.

### Why?

* We want to display a chevron icon.
* Expo provides ready-to-use icon libraries.

### Add This Import

-------------------code----------------------
import { MaterialCommunityIcons } from '@expo/vector-icons';
-------------------code----------------------

### Important Cleanup

* Remove unused imports like `TouchableOpacity` (if present).
* Keep third-party imports grouped together.
* Keep local project imports grouped separately.

### Organized Import Structure

-------------------code----------------------
// React Native core
import { Image, StyleSheet, TouchableHighlight, View } from 'react-native';

// Third-party libraries
import Swipeable from "react-native-gesture-handler/Swipeable";
import { MaterialCommunityIcons } from '@expo/vector-icons';

// Local imports
import colors from '../config/colors';
import AppText from './AppText';
-------------------code----------------------

Best Practice:

* Always group imports by category.
* Remove unused imports immediately.

---

# 3. Step 2 – Add the Chevron Icon

We want to place the chevron icon to the right of the title/subtitle section.

### Where to Add It?

Inside the main container, right after `detailsContainer`.

### Add This Code

-------------------code----------------------
<MaterialCommunityIcons
  name="chevron-right"
  size={25}
/>
-------------------code----------------------

So the JSX becomes:

-------------------code----------------------
<View style={styles.container}>

  {iconComponent}

  {image && (
    <Image
      source={image}
      style={styles.image}
    />
  )}

  <View style={styles.detailsContainer}>
    <AppText style={styles.title}>
      {title}
    </AppText>

    {subtitle && (
      <AppText style={styles.subtitle}>
        {subtitle}
      </AppText>
    )}
  </View>

  <MaterialCommunityIcons
    name="chevron-right"
    size={25}
  />

</View>
-------------------code----------------------

At this stage, the icon appears — but alignment is not correct yet.

---

# 4. Step 3 – Push the Chevron to the Right

Currently, the icon sits next to the text.

We want:

* Text to take available space.
* Chevron to stay on the far right.

### Solution: Use `flex: 1` on detailsContainer

In styles:

-------------------code----------------------
detailsContainer: {
  marginLeft: 10,
  justifyContent: "center",
  flex: 1,
},
-------------------code----------------------

Why this works:

* The container direction is `row`.
* `flex: 1` makes `detailsContainer` expand.
* The chevron gets pushed to the far right.

---

# 5. Step 4 – Vertically Center the Content

Now we want everything centered vertically.

Since:

-------------------code----------------------
flexDirection: 'row'
-------------------code----------------------

This means:

* Main axis → horizontal
* Cross axis → vertical

To align items vertically, we use:

-------------------code----------------------
alignItems: 'center'
-------------------code----------------------

Update container style:

-------------------code----------------------
container: {
  flexDirection: 'row',
  padding: 15,
  backgroundColor: colors.white,
  alignItems: 'center',
},
-------------------code----------------------

Now the icon, image, and text align properly.

---

# 6. Step 5 – Improve Icon Color

The default icon color is pure black, which is too strong.

We want to use medium gray from our color palette.

Update icon:

-------------------code----------------------
<MaterialCommunityIcons
  name="chevron-right"
  size={25}
  color={colors.medium}
/>
-------------------code----------------------

Now the UI looks softer and more professional.

---

# 7. Full Final Code

-------------------code----------------------
import { Image, StyleSheet, TouchableHighlight, View } from 'react-native';
import Swipeable from "react-native-gesture-handler/Swipeable";
import { MaterialCommunityIcons } from '@expo/vector-icons';

import colors from '../config/colors';
import AppText from './AppText';

function ListItem({
  title,
  subtitle,
  image,
  iconComponent,
  onPress,
  renderRightActions
}) {
  return (
    <Swipeable renderRightActions={renderRightActions}>
      <TouchableHighlight
        underlayColor={colors.light}
        onPress={onPress}
      >
        <View style={styles.container}>

          {iconComponent}

          {image && (
            <Image
              source={image}
              style={styles.image}
            />
          )}

          <View style={styles.detailsContainer}>
            <AppText style={styles.title}>
              {title}
            </AppText>

            {subtitle && (
              <AppText style={styles.subtitle}>
                {subtitle}
              </AppText>
            )}
          </View>

          <MaterialCommunityIcons
            name="chevron-right"
            size={25}
            color={colors.medium}
          />

        </View>
      </TouchableHighlight>
    </Swipeable>
  );
}

const styles = StyleSheet.create({
  container: {
    flexDirection: 'row',
    padding: 15,
    backgroundColor: colors.white,
    alignItems: 'center',
  },

  detailsContainer: {
    marginLeft: 10,
    justifyContent: "center",
    flex: 1,
  },

  image: {
    width: 70,
    height: 70,
    borderRadius: 35,
  },

  title: {
    fontWeight: '500',
  },

  subtitle: {
    color: colors.medium,
  },
});

export default ListItem;
-------------------code----------------------

*** 3- Handling Long Text ***
# Handling Long Text in React Native (Improving AppText and ListItem)

## 1. Problem Overview

Long text is a common UI issue in mobile applications.

When a title or subtitle is too long:

* It can overflow.
* It can break layout.
* It can make the UI look unprofessional.

In our case:

* The `ListItem` component looks bad when the title or subtitle is too long.

Solution:

* Truncate text using the `numberOfLines` prop.
* Ensure our custom `AppText` component forwards all props correctly.

---

# 2. Step 1 – Truncate Title in ListItem

In React Native, the `Text` component supports a prop called:

-------------------code----------------------
numberOfLines
-------------------code----------------------

When set:

* It limits how many lines are displayed.
* Extra text is truncated automatically.

### Update Title

Go to `ListItem.js` and update the title:

-------------------code----------------------
<AppText
  style={styles.title}
  numberOfLines={1}
>
  {title}
</AppText>
-------------------code----------------------

Expected result:

* Title should be limited to one line.
* Extra text should be truncated.

But nothing changes.

Why?

Because our `AppText` component does not pass additional props to the underlying `Text` component.

---

# 3. Step 2 – Fix AppText to Support Extra Props

Current `AppText` implementation:

-------------------code----------------------
function AppText({ children }) {
  return <Text style={defaultStyles.text}>{children}</Text>;
}
-------------------code----------------------

Problem:

* It only accepts `children`.
* It ignores any additional props like:

  * `numberOfLines`
  * `ellipsizeMode`
  * `onPress`
  * `style`
  * etc.

We need to forward all extra props.

---

# 4. Step 3 – Use the Rest Operator

We use the rest operator (`...rest`) to collect additional props.

### Updated Version

-------------------code----------------------
function AppText({ children, style, ...otherProps }) {
  return (
    <Text style={[defaultStyles.text, style]} {...otherProps}>
      {children}
    </Text>
  );
}
-------------------code----------------------

What changed:

1. Added `style` support.
2. Used `...otherProps` to collect remaining props.
3. Spread them into `<Text />`.

Now:

* `numberOfLines` works.
* Any future prop works automatically.
* The component is reusable and flexible.

---

# 5. Step 4 – Limit Subtitle Lines

Now go back to `ListItem.js`.

For the subtitle, allow more space.

### Update Subtitle

-------------------code----------------------
<AppText
  style={styles.subtitle}
  numberOfLines={2}
>
  {subtitle}
</AppText>
-------------------code----------------------

Result:

* Title → maximum 1 line.
* Subtitle → maximum 2 lines.
* Layout stays clean and consistent.

---

# 6. Final AppText Code

-------------------code----------------------
import React from "react";
import { Text } from "react-native";
import defaultStyles from "../config/styles";

function AppText({ children, style, ...otherProps }) {
  return (
    <Text style={[defaultStyles.text, style]} {...otherProps}>
      {children}
    </Text>
  );
}

export default AppText;
-------------------code----------------------

---

# 8. Important Concepts

### 1. Always Test With Long Text

Many UI bugs only appear when:

* Text is unusually long.
* Real user data is used.

Never test with short placeholder text only.

---

### 2. The Rest Operator

-------------------code----------------------
...otherProps
-------------------code----------------------

Allows:

* Flexible reusable components.
* Clean abstraction.
* Future-proof design.

Without it:

* Your custom component becomes limited.
* You constantly need to modify it for new props.

---

### 3. Style Merging Pattern

-------------------code----------------------
style={[defaultStyles.text, style]}
-------------------code----------------------

Why use array syntax?

* It merges default styles with custom styles.
* Later styles override earlier ones.
* Makes the component extensible.

---

# 9. Best Practices

* Always design reusable components to forward props.
* Never block native component capabilities.
* Use `numberOfLines` for layout safety.
* Test with edge cases (long text, empty text).
* Keep UI consistent across screens.

*** 4- Improving the Messages Screen ***
# Fixing the Screen Layout Cutoff Issue

## 1. Problem Overview

When pulling down a list (e.g., FlatList with pull-to-refresh), a visual cutoff appears at the top of the screen.

This issue happens because:

* The inner `View` does not expand to fill available space.
* It only grows to fit its content (default behavior).
* As a result, the layout breaks during refresh interactions.

---

# 2. Understanding the Original Implementation

Initial `Screen` component:

-------------------code----------------------
function Screen({ children, style }) {
  return (
    <SafeAreaView style={[styles.screen, style]}>
      <View style={style}>
        {children}
      </View>
    </SafeAreaView>
  );
}
-------------------code----------------------

### Styles

-------------------code----------------------
const styles = StyleSheet.create({
  screen: {
    paddingTop: Constants.statusBarHeight,
    flex: 1,
  },
});
-------------------code----------------------

Important points:

* `SafeAreaView` has `flex: 1`, so it fills the screen.
* The inner `View` does not have `flex: 1`.
* By default, `View` grows only enough to fit its content.

That is the root cause of the cutoff.

---

# 3. Why the Inner View Was Added

Originally:

* Only `SafeAreaView` was used.
* Later, a `View` was added because `SafeAreaView` did not properly support horizontal padding at the time.
* The extra `View` acts as a layout wrapper.

However:

* That wrapper must also expand to full height.
* Otherwise, layout issues occur.

---

# 4. Debugging Technique: Using Background Colors

A practical debugging technique:

Temporarily apply background colors to visualize layout behavior.

Example:

-------------------code----------------------
<SafeAreaView style={[styles.screen, { backgroundColor: "yellow" }]}>
  <View style={{ backgroundColor: "orange" }}>
    {children}
  </View>
</SafeAreaView>
-------------------code----------------------

What happens?

* Yellow covers the entire screen.
* Orange only covers the content area.
* No orange in empty space → confirms the inner `View` is not expanding.

This confirms the layout issue.

---

# 5. Fix: Make the Inner View Expand

Solution:

Add `flex: 1` to the inner `View`.

Temporary test:

-------------------code----------------------
<View style={{ flex: 1 }}>
-------------------code----------------------

Result:

* The inner `View` now fills available space.
* Pull-to-refresh cutoff disappears.

---

# 6. Clean and Proper Fix

Instead of inline styling, define a new style.

### Step 1 – Add View Style

-------------------code----------------------
const styles = StyleSheet.create({
  screen: {
    paddingTop: Constants.statusBarHeight,
    flex: 1,
  },
  view: {
    flex: 1,
  },
});
-------------------code----------------------

### Step 2 – Apply Styles Properly

Important rule:

* Apply internal styles first.
* Apply external styles afterward so they can override.

Update component:

-------------------code----------------------
function Screen({ children, style }) {
  return (
    <SafeAreaView style={styles.screen}>
      <View style={[styles.view, style]}>
        {children}
      </View>
    </SafeAreaView>
  );
}
-------------------code----------------------

Now:

* `SafeAreaView` fills screen.
* Inner `View` also fills screen.
* External styles can still be passed safely.
* No more cutoff during refresh.

---

# 7. Full Final Code

-------------------code----------------------
import { SafeAreaView, StyleSheet, View } from "react-native";
import Constants from "expo-constants";

function Screen({ children, style }) {
  return (
    <SafeAreaView style={styles.screen}>
      <View style={[styles.view, style]}>
        {children}
      </View>
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  screen: {
    paddingTop: Constants.statusBarHeight,
    flex: 1,
  },
  view: {
    flex: 1,
  },
});

export default Screen;
-------------------code----------------------

---

# 8. Important Concepts

## 8.1 Default Behavior of View

* `View` grows only as much as its content.
* It does not fill available space unless `flex` is set.

## 8.2 Why `flex: 1` Is Important

* Makes a component expand to fill available space.
* Prevents layout glitches.
* Essential for scrollable components.

## 8.3 Style Order Matters

-------------------code----------------------
style={[styles.view, style]}
-------------------code----------------------

Why?

* Styles applied later override earlier ones.
* Internal defaults come first.
* External overrides come last.

---

# 9. Best Practices

* When debugging layout issues, temporarily use background colors.
* Always ensure layout wrappers use `flex: 1` when needed.
* Avoid inline style objects in production code.
* Keep internal styles separate from external overrides.
* Test interactions like pull-to-refresh, scrolling, and rotation.

---

# 10. Summary

In this lecture, we:

1. Identified a cutoff issue during pull-to-refresh.
2. Discovered the inner `View` was not expanding.
3. Used background colors to debug layout behavior.
4. Applied `flex: 1` to fix the issue.
5. Refactored the component for clean, reusable structure.

Key takeaway:

When building screen wrappers, always ensure both the root container and its main content wrapper use `flex: 1` to avoid layout bugs.
