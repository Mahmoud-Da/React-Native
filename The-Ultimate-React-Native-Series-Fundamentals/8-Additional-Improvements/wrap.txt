*** 3- Handling Long Text ***
# Handling Long Text in React Native (Improving AppText and ListItem)

## 1. Problem Overview

Long text is a common UI issue in mobile applications.

When a title or subtitle is too long:

* It can overflow.
* It can break layout.
* It can make the UI look unprofessional.

In our case:

* The `ListItem` component looks bad when the title or subtitle is too long.

Solution:

* Truncate text using the `numberOfLines` prop.
* Ensure our custom `AppText` component forwards all props correctly.

---

# 2. Step 1 – Truncate Title in ListItem

In React Native, the `Text` component supports a prop called:

-------------------code----------------------
numberOfLines
-------------------code----------------------

When set:

* It limits how many lines are displayed.
* Extra text is truncated automatically.

### Update Title

Go to `ListItem.js` and update the title:

-------------------code----------------------
<AppText
  style={styles.title}
  numberOfLines={1}
>
  {title}
</AppText>
-------------------code----------------------

Expected result:

* Title should be limited to one line.
* Extra text should be truncated.

But nothing changes.

Why?

Because our `AppText` component does not pass additional props to the underlying `Text` component.

---

# 3. Step 2 – Fix AppText to Support Extra Props

Current `AppText` implementation:

-------------------code----------------------
function AppText({ children }) {
  return <Text style={defaultStyles.text}>{children}</Text>;
}
-------------------code----------------------

Problem:

* It only accepts `children`.
* It ignores any additional props like:

  * `numberOfLines`
  * `ellipsizeMode`
  * `onPress`
  * `style`
  * etc.

We need to forward all extra props.

---

# 4. Step 3 – Use the Rest Operator

We use the rest operator (`...rest`) to collect additional props.

### Updated Version

-------------------code----------------------
function AppText({ children, style, ...otherProps }) {
  return (
    <Text style={[defaultStyles.text, style]} {...otherProps}>
      {children}
    </Text>
  );
}
-------------------code----------------------

What changed:

1. Added `style` support.
2. Used `...otherProps` to collect remaining props.
3. Spread them into `<Text />`.

Now:

* `numberOfLines` works.
* Any future prop works automatically.
* The component is reusable and flexible.

---

# 5. Step 4 – Limit Subtitle Lines

Now go back to `ListItem.js`.

For the subtitle, allow more space.

### Update Subtitle

-------------------code----------------------
<AppText
  style={styles.subtitle}
  numberOfLines={2}
>
  {subtitle}
</AppText>
-------------------code----------------------

Result:

* Title → maximum 1 line.
* Subtitle → maximum 2 lines.
* Layout stays clean and consistent.

---

# 6. Final AppText Code

-------------------code----------------------
import React from "react";
import { Text } from "react-native";
import defaultStyles from "../config/styles";

function AppText({ children, style, ...otherProps }) {
  return (
    <Text style={[defaultStyles.text, style]} {...otherProps}>
      {children}
    </Text>
  );
}

export default AppText;
-------------------code----------------------

*** 4- Improving the Messages Screen ***
# Fixing the Screen Layout Cutoff Issue

## 1. Problem Overview

When pulling down a list (e.g., FlatList with pull-to-refresh), a visual cutoff appears at the top of the screen.

This issue happens because:

* The inner `View` does not expand to fill available space.
* It only grows to fit its content (default behavior).
* As a result, the layout breaks during refresh interactions.

---

# 2. Understanding the Original Implementation

Initial `Screen` component:

-------------------code----------------------
function Screen({ children, style }) {
  return (
    <SafeAreaView style={[styles.screen, style]}>
      <View style={style}>
        {children}
      </View>
    </SafeAreaView>
  );
}
-------------------code----------------------

### Styles

-------------------code----------------------
const styles = StyleSheet.create({
  screen: {
    paddingTop: Constants.statusBarHeight,
    flex: 1,
  },
});
-------------------code----------------------

Important points:

* `SafeAreaView` has `flex: 1`, so it fills the screen.
* The inner `View` does not have `flex: 1`.
* By default, `View` grows only enough to fit its content.

That is the root cause of the cutoff.

---

# 3. Why the Inner View Was Added

Originally:

* Only `SafeAreaView` was used.
* Later, a `View` was added because `SafeAreaView` did not properly support horizontal padding at the time.
* The extra `View` acts as a layout wrapper.

However:

* That wrapper must also expand to full height.
* Otherwise, layout issues occur.

---

# 4. Debugging Technique: Using Background Colors

A practical debugging technique:

Temporarily apply background colors to visualize layout behavior.

Example:

-------------------code----------------------
<SafeAreaView style={[styles.screen, { backgroundColor: "yellow" }]}>
  <View style={{ backgroundColor: "orange" }}>
    {children}
  </View>
</SafeAreaView>
-------------------code----------------------

What happens?

* Yellow covers the entire screen.
* Orange only covers the content area.
* No orange in empty space → confirms the inner `View` is not expanding.

This confirms the layout issue.

---

# 5. Fix: Make the Inner View Expand

Solution:

Add `flex: 1` to the inner `View`.

Temporary test:

-------------------code----------------------
<View style={{ flex: 1 }}>
-------------------code----------------------

Result:

* The inner `View` now fills available space.
* Pull-to-refresh cutoff disappears.

---

# 6. Clean and Proper Fix

Instead of inline styling, define a new style.

### Step 1 – Add View Style

-------------------code----------------------
const styles = StyleSheet.create({
  screen: {
    paddingTop: Constants.statusBarHeight,
    flex: 1,
  },
  view: {
    flex: 1,
  },
});
-------------------code----------------------

### Step 2 – Apply Styles Properly

Important rule:

* Apply internal styles first.
* Apply external styles afterward so they can override.

Update component:

-------------------code----------------------
function Screen({ children, style }) {
  return (
    <SafeAreaView style={styles.screen}>
      <View style={[styles.view, style]}>
        {children}
      </View>
    </SafeAreaView>
  );
}
-------------------code----------------------

Now:

* `SafeAreaView` fills screen.
* Inner `View` also fills screen.
* External styles can still be passed safely.
* No more cutoff during refresh.

---

# 7. Full Final Code

-------------------code----------------------
import { SafeAreaView, StyleSheet, View } from "react-native";
import Constants from "expo-constants";

function Screen({ children, style }) {
  return (
    <SafeAreaView style={styles.screen}>
      <View style={[styles.view, style]}>
        {children}
      </View>
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  screen: {
    paddingTop: Constants.statusBarHeight,
    flex: 1,
  },
  view: {
    flex: 1,
  },
});

export default Screen;
-------------------code----------------------

---

# 8. Important Concepts

## 8.1 Default Behavior of View

* `View` grows only as much as its content.
* It does not fill available space unless `flex` is set.

## 8.2 Why `flex: 1` Is Important

* Makes a component expand to fill available space.
* Prevents layout glitches.
* Essential for scrollable components.

## 8.3 Style Order Matters

-------------------code----------------------
style={[styles.view, style]}
-------------------code----------------------

Why?

* Styles applied later override earlier ones.
* Internal defaults come first.
* External overrides come last.

---

# 9. Best Practices

* When debugging layout issues, temporarily use background colors.
* Always ensure layout wrappers use `flex: 1` when needed.
* Avoid inline style objects in production code.
* Keep internal styles separate from external overrides.
* Test interactions like pull-to-refresh, scrolling, and rotation.

---

# 10. Summary

In this lecture, we:

1. Identified a cutoff issue during pull-to-refresh.
2. Discovered the inner `View` was not expanding.
3. Used background colors to debug layout behavior.
4. Applied `flex: 1` to fix the issue.
5. Refactored the component for clean, reusable structure.

Key takeaway:

When building screen wrappers, always ensure both the root container and its main content wrapper use `flex: 1` to avoid layout bugs.


*** 5- Fixing the Auto Import Issue ***
# Fixing Auto Import in VS Code (React Native Project)

## 1. Problem Overview

Auto import was not working in VS Code.

Example:

* Typing a component like `AppText`
* No auto-import suggestions appear
* IntelliSense does not recognize project files

This usually happens due to:

* Conflicting extensions
* Missing project configuration

---

# 2. Step 1 – Check Installed Extensions

Before changing project configuration:

1. Open VS Code Extensions panel.
2. Look for extensions related to:

   * Auto import
   * JavaScript imports
   * Path IntelliSense
3. Uninstall any third-party auto-import extensions.

Why?

* VS Code already supports auto-import natively.
* Older extensions can conflict with built-in IntelliSense.
* Especially common if extensions were installed years ago.

Best Practice:
Only use necessary extensions. Avoid redundant tools.

---

# 3. Step 2 – Add jsconfig.json

If removing extensions does not fix the issue, create a configuration file.

### Create a file in the project root:

-------------------code----------------------
jsconfig.json
-------------------code----------------------

Make sure:

* It is in the root directory.
* The filename is spelled exactly: `jsconfig.json`.

---

# 4. Step 3 – Configure jsconfig.json

Add the following configuration:

-------------------code----------------------
{
  "exclude": ["node_modules"]
}
-------------------code----------------------

---

# 5. Why This Works

## 5.1 What jsconfig.json Does

* Informs VS Code that this is a structured JavaScript project.
* Enables better IntelliSense.
* Improves module resolution.
* Activates advanced auto-import behavior.

Even if the project is not TypeScript, this file helps VS Code treat it like a structured project.

---

## 5.2 Why Excluding node_modules Is Important

-------------------code----------------------
"exclude": ["node_modules"]
-------------------code----------------------

This tells IntelliSense:

* Do not scan the entire `node_modules` directory.
* Avoid unnecessary indexing.
* Improve performance.
* Prevent IntelliSense slowdowns in large projects.

If your project is large and this is not excluded:

* Auto import may become slow.
* IntelliSense may lag.

---

# 6. Step 4 – Restart VS Code

If auto import still does not work:

1. Close VS Code completely.
2. Reopen the project.
3. Try importing a component again.

Restarting refreshes IntelliSense indexing.

---

# 7. Testing the Fix

After applying the fix:

* Type a component name, e.g.:

-------------------code----------------------js
AppText
-------------------code----------------------

* VS Code should now:

  * Suggest auto import.
  * Insert the correct import statement automatically.

Example of expected auto import:

-------------------code----------------------js
import AppText from "../components/AppText";
-------------------code----------------------

---

# 8. Full Final jsconfig.json

-------------------code----------------------
{
  "exclude": ["node_modules"]
}
-------------------code----------------------

Place this file in the project root directory.

---

# 9. Best Practices

1. Avoid installing unnecessary extensions.
2. Use built-in VS Code features whenever possible.
3. Always configure large projects properly.
4. Exclude heavy folders like `node_modules` for performance.
5. Restart VS Code after configuration changes.

---

# 10. Summary

In this lecture, we fixed auto-import issues in VS Code by:

1. Removing outdated auto-import extensions.
2. Creating a `jsconfig.json` file.
3. Excluding the `node_modules` folder.
4. Restarting VS Code.

Key takeaway:

Proper project configuration is essential for reliable IntelliSense and auto-import functionality in React Native and JavaScript projects.

function AppPicker({
  icon,
  items,
  placeholder,
  selectedItem,
  onSelectItem,
  width = "100%"
}) {
  const [modalVisible, setModalVisible] = useState(false);

  return (
    <>
      <TouchableWithoutFeedback
        onPress={() => setModalVisible(true)}
      >
        <View style={[styles.container, { width }]}>
          {icon && (
            <MaterialCommunityIcons
              name={icon}
              size={20}
              color={colors.medium}
              style={styles.icon}
            />
          )}

          {selectedItem ? (
            <AppText style={styles.text}>
              {selectedItem.label}
            </AppText>
          ) : (
            <AppText style={styles.placeholder}>
              {placeholder}
            </AppText>
          )}

          <MaterialCommunityIcons
            name="chevron-down"
            size={20}
            color={colors.medium}
          />
        </View>
      </TouchableWithoutFeedback>

      <Modal visible={modalVisible} animationType="slide">
        <Screen>
          <Button
            title="Close"
            onPress={() => setModalVisible(false)}
          />
          <FlatList
            data={items}
            keyExtractor={(item) =>
              item.value.toString()
            }
            renderItem={({ item }) => (
              <PickerItem
                label={item.label}
                onPress={() => {
                  setModalVisible(false);
                  onSelectItem(item);
                }}
              />
            )}
          />
        </Screen>
      </Modal>
    </>
  );
}

# 11. Best Practices

1. Never hard-code layout values inside reusable components.
2. Always provide sensible default values.
3. Pass props down cleanly.
4. Use style arrays for flexibility.
5. Keep UI proportional to content.
