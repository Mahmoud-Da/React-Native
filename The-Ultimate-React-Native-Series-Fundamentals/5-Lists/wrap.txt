# Building Lists in React Native

## 1. Introduction

Almost every mobile application needs to display a **list of data**.

Examples:

* Messages in a chat app
* Products in a marketplace
* Notifications
* Contacts
* Posts in a social feed

Because lists are so common, understanding how to build them properly is a core React Native skill.

---

## 2. Why Lists Are Important

Lists allow you to:

1. Display dynamic data from an array
2. Render large amounts of content efficiently
3. Build scalable and reusable UI patterns
4. Improve performance using optimized components like `FlatList`

In real-world apps, most screens are built around lists.

---

## 3. What You Will Build in This Section

In this section, you will:

1. Build three new screens
2. Create multiple reusable components
3. Learn how to structure list-based layouts
4. Improve your app architecture
5. Make your UI more dynamic and production-ready

This section moves the app from static layouts to data-driven interfaces.

---

## 4. Core Concept: Rendering Lists

In React Native, lists are usually built using:

* `FlatList` (recommended for most cases)
* `SectionList` (for grouped data)
* `ScrollView` (not recommended for large lists)

The most important one is:

### FlatList

It:

* Efficiently renders only visible items
* Handles large datasets well
* Supports separators, headers, pull-to-refresh, and more

---

## 5. High-Level Example of a Basic FlatList

Here is a simple conceptual example:

-------------------code----------------------
import React from "react";
import { View, Text, FlatList } from "react-native";

const data = [
  { id: "1", title: "First Item" },
  { id: "2", title: "Second Item" },
  { id: "3", title: "Third Item" },
];

function ExampleScreen() {
  return (
    <View>
      <FlatList
        data={data}
        keyExtractor={(item) => item.id}
        renderItem={({ item }) => (
          <Text>{item.title}</Text>
        )}
      />
    </View>
  );
}

export default ExampleScreen;
-------------------code----------------------

This is the foundation of list rendering in React Native.

# Building the Messages Screen with FlatList

The goal of this lesson is to build a **Messages Screen** that displays a list of messages using React Native’s `FlatList` component.

This is the first real example of rendering **dynamic lists of data** in the app.

---

## 2. Why Use FlatList

`FlatList` is the standard way to render lists in React Native because it is:

1. Fully cross-platform (iOS and Android)
2. Optimized for performance
3. Able to render large datasets efficiently
4. Supports advanced features such as:

   * Headers and footers
   * Item separators
   * Pull-to-refresh
   * Infinite scrolling

## 5. Configuring FlatList

`FlatList` requires **three essential props**.

---

### 5.1 data Prop

This tells FlatList what data to render.

-------------------code----------------------
data={messages}
-------------------code----------------------

---

### 5.2 keyExtractor Prop

Each item in a list must have a **unique key**.

FlatList requires keys to be **strings**, so we convert `id` to a string.

-------------------code----------------------
keyExtractor={(message) => message.id.toString()}
-------------------code----------------------

---

### 5.3 renderItem Prop

This function tells FlatList **how to render each item**.

The parameter is an object that includes:

* `item`
* `index`
* `separators`

We destructure `item` directly.

-------------------code----------------------
renderItem={({ item }) => (
  <ListItem
    title={item.title}
    subtitle={item.description}
    image={item.image}
  />
)}
-------------------code----------------------

# Fixing Safe Area Issues and Creating a Reusable Screen Component

## 1. Problem: Content Under the Status Bar

When rendering the `MessagesScreen`, the content appears:

* Under the status bar on Android
* Properly spaced on iOS (after using `SafeAreaView`)

### Why?

* `SafeAreaView` only fully solves this issue on **iOS**
* On Android, additional padding is required

---

# Part 1: Basic SafeAreaView Fix

## 2. Wrapping Content in SafeAreaView

### Step 1: Import SafeAreaView

-------------------code----------------------

-------------------code----------------------

### Step 2: Wrap the Screen Content

-------------------code----------------------

  <FlatList ... />
</SafeAreaView>
-------------------code----------------------

Result:

* iOS issue resolved
* Android still has overlap

---

# Part 2: Fixing Android with Platform and StatusBar

## 3. Detect Platform and Apply Padding

### Step 1: Import Required APIs

-------------------code----------------------
import { StyleSheet, Platform, StatusBar } from "react-native";
-------------------code----------------------

### Step 2: Create a Style for the Screen

-------------------code----------------------
const styles = StyleSheet.create({
  screen: {
    paddingTop:
      Platform.OS === "android" ? StatusBar.currentHeight : 0,
  },
});
-------------------code----------------------

### Step 3: Apply the Style

-------------------code----------------------

  <FlatList ... />
</SafeAreaView>
-------------------code----------------------

Result:

* Works on iOS
* Works on Android

However, this approach requires repeating the same logic in every screen.

# Part 3: Better Approach Using expo-constants

Instead of manually checking the platform, we can use `expo-constants`.

## 4. Install expo-constants

-------------------code----------------------

-------------------code----------------------

---

-------------------code----------------------

* No curly braces
* It is a default export

---

## 6. Use Constants for Status Bar Height

Replace the previous platform logic with:

-------------------code----------------------
const styles = StyleSheet.create({
  screen: {
    paddingTop: Constants.statusBarHeight,
  },
});
-------------------code----------------------

Why this works:

* On Android → returns 24px
* On iOS → returns 44px
* SafeAreaView already handles iOS safe area
* Extra padding does not negatively affect iOS

Now:

* Platform API is no longer needed
* StatusBar API is no longer needed
* Code is simpler

# Adding Separators and Padding to Lists in React Native

---

## 1. Problem: Adding a Separator Between List Items

We want a visual separator between items in a `FlatList`.

**Two possible approaches:**

1. **Add a border inside `ListItem`**

   * Pros: Easy to implement
   * Cons: Adds extra line after the last item, requires hacks to remove it → not recommended

2. **Use `FlatList`’s `ItemSeparatorComponent` prop**

   * Pros: Clean solution, no extra lines after the last item
   * Recommended approach

---

## 2. Using `ItemSeparatorComponent` in FlatList

### Step 1: Implement Inline Separator

-------------------code----------------------
<FlatList
  data={messages}
  keyExtractor={(message) => message.id.toString()}
  renderItem={({ item }) => (
    <ListItem
      title={item.title}
      subtitle={item.description}
      image={item.image}
    />
  )}
  ItemSeparatorComponent={() => (
    <View
      style={{
        width: "100%",
        height: 1,
        backgroundColor: "black",
      }}
    />
  )}
/>
-------------------code----------------------

Works: no separator after the last item

**Note:** Don't forget to import `View`:

-------------------code----------------------
import { View } from "react-native";
-------------------code----------------------

---

## 3. Making the Separator Reusable

### Step 1: Create a New Component

**File:** `components/ListItemSeparator.js`

export default ListItemSeparator;
-------------------code----------------------

# 6. Summary of Best Practices

1. **Never hardcode separators inside `ListItem`** → use `ItemSeparatorComponent`.
2. **Make separators reusable** for maintainability.
3. **Use colors from a palette** instead of hardcoding.
4. **Add padding inside items** to prevent content from touching screen edges.
5. `FlatList` props used:

   * `data` → array of items
   * `keyExtractor` → unique ID
   * `renderItem` → renders each list item
   * `ItemSeparatorComponent` → renders separator between items

# Handling Selections in List Items in React Native

---

## 1. Problem: List Items Are Not Selectable

Currently, our `ListItem` component does not respond when tapped.
We want a **visual feedback** and the ability to perform an action when a user selects an item.

---

## 2. Wrapping List Items in a Touchable Component

React Native provides multiple touchable components:

| Component                  | Description                                            |
| -------------------------- | ------------------------------------------------------ |
| `TouchableOpacity`         | Changes opacity briefly on tap; subtle visual feedback |
| `TouchableHighlight`       | Highlights item with a background color on tap         |
| `TouchableWithoutFeedback` | No visual feedback; just detects taps                  |

**Decision:** Use `TouchableHighlight` because we want a **background color change** when selecting a list item.

---

## 3. Implementing TouchableHighlight in ListItem

### Step 1: Wrap content with `TouchableHighlight`

-------------------code----------------------
import React from 'react';
import { View, Image, StyleSheet, TouchableHighlight } from 'react-native';
import AppText from './AppText';
import colors from '../config/colors';

function ListItem({ title, subtitle, image, onPress }) {
  return (
    <TouchableHighlight
      underlayColor={colors.light}
      onPress={onPress}
    >

      <View style={styles.container}>
        <Image source={image} style={styles.image} />

        <View>
          <AppText style={styles.title}>{title}</AppText>
          <AppText style={styles.subtitle}>{subtitle}</AppText>
        </View>
      </View>
    </TouchableHighlight>
  );
}

const styles = StyleSheet.create({
  container: {
    flexDirection: 'row',
    padding: 15,
  },
  image: {
    width: 70,
    height: 70,
    borderRadius: 35,
    marginRight: 10,
  },
  title: {
    fontWeight: '500',
  },
  subtitle: {
    color: colors.medium,
  },
});

export default ListItem;
-------------------code----------------------

---

## 4. Passing Selection Logic from Parent

The `ListItem` component should **not decide what happens on tap**.
Instead, it accepts an `onPress` prop from its parent (consumer).

### Step 1: Use `onPress` in MessagesScreen

-------------------code----------------------
import React from "react";
import { FlatList } from "react-native";
import Screen from "./Screen";
import ListItem from "../components/ListItem";
import ListItemSeparator from "../components/ListItemSeparator";

const messages = [
  {
    id: 1,
    title: "t1",
    description: "d1",
    image: require("../assets/mosh.jpg"),
  },
  {
    id: 2,
    title: "t2",
    description: "d2",
    image: require("../assets/mosh.jpg"),
  },
];

function MessagesScreen() {
  return (
    <Screen>
      <FlatList
        data={messages}
        keyExtractor={(message) => message.id.toString()}
        renderItem={({ item }) => (
          <ListItem
            title={item.title}
            subtitle={item.description}
            image={item.image}
            onPress={() => console.log("Message selected:", item)}
          />
        )}
        ItemSeparatorComponent={ListItemSeparator}
      />
    </Screen>
  );
}

export default MessagesScreen;
-------------------code----------------------

Now, when a list item is tapped:

* The background briefly changes to **light gray**
* The parent handles the action (e.g., logs the item, navigates to another screen)

---

## 5. Best Practices

1. **Use `TouchableHighlight` for list items** for proper visual feedback.
2. **Keep the `ListItem` component reusable**:

   * Don’t hardcode what happens on press
   * Pass an `onPress` prop from the parent
3. **Use colors from a palette** for consistency
4. **Encapsulate padding and styling** in `ListItem` for cleaner layout
5. **Combine with separators** for clean lists
