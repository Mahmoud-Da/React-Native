1. Login Screen

# 2. Why Forms Need Special Handling

Forms are more complex than normal components because they must handle:

* User input
* Validation
* Errors
* Submission
* Field state (touched, dirty, etc.)

Without a library, managing all of this manually becomes messy.

Example of manual form handling (not recommended):

-------------------code----------------------
const [email, setEmail] = useState("");
const [password, setPassword] = useState("");

<TextInput
   value={email}
   onChangeText={setEmail}
/>

<TextInput
   value={password}
   onChangeText={setPassword}
/>
-------------------code----------------------

Problems:

* Hard to scale
* Hard to validate
* Hard to manage many fields

Solution: Use Formik

# 11. Full Final Code Example

This is a complete working example.

-------------------code----------------------
import React from "react";
import { View, TextInput, Button } from "react-native";
import { Formik } from "formik";
import * as Yup from "yup";

const validationSchema = Yup.object().shape({

   email: Yup.string()
      .required("Email is required")
      .email("Invalid email"),

   password: Yup.string()
      .required("Password is required")
      .min(4, "Password too short")

});

export default function LoginScreen() {

   return (

      <View style={{ padding: 20 }}>

         <Formik

            initialValues={{
               email: "",
               password: ""
            }}

            validationSchema={validationSchema}

            onSubmit={(values) => {

               console.log(values);

            }}

         >

            {({

               handleChange,
               handleSubmit,
               values

            }) => (

               <>

                  <TextInput

                     placeholder="Email"

                     value={values.email}

                     onChangeText={handleChange("email")}

                     style={{
                        borderWidth: 1,
                        marginBottom: 10,
                        padding: 10
                     }}

                  />

                  <TextInput

                     placeholder="Password"

                     value={values.password}

                     onChangeText={handleChange("password")}

                     secureTextEntry

                     style={{
                        borderWidth: 1,
                        marginBottom: 10,
                        padding: 10
                     }}

                  />

                  <Button

                     title="Login"

                     onPress={handleSubmit}

                  />

               </>

            )}

         </Formik>

      </View>

   );

}
-------------------code----------------------

*** 3- Building Better Forms with Formik ***
# Using Formik in Login Screen — Structured Notes

This lecture introduces **Formik** and replaces manual form state handling with Formik. This makes forms cleaner, scalable, and easier to maintain.

---

# 1. Problem With Manual Forms

Previously, you used `useState` to manage form inputs:

Example:

-------------------code----------------------
const [email, setEmail] = useState("");
const [password, setPassword] = useState("");
-------------------code----------------------

Problems with this approach:

As the number of fields increases:

* More state variables needed
* More event handlers needed
* Harder to validate inputs
* More complex code

Example with 5 fields:

-------------------code----------------------
const [field1, setField1] = useState("");
const [field2, setField2] = useState("");
const [field3, setField3] = useState("");
const [field4, setField4] = useState("");
const [field5, setField5] = useState("");
-------------------code----------------------

This becomes difficult to manage.

Solution: Use Formik

---

# 2. What is Formik

Formik is a popular library that:

* Tracks form state automatically
* Handles input changes
* Handles submission
* Supports validation

Main benefit:

Removes need for useState for form fields.

Formik manages everything internally.

# Form Validation with Yup and Formik — Structured Notes

This lecture explains how to add **form validation** using **Yup**, and integrate it with **Formik** to validate email and password fields.

---

# 1. Why Validation is Needed

Validation ensures users enter correct data.

Examples:

* Email must be valid format
* Password must have minimum length
* Required fields cannot be empty

Without validation:

* Invalid data can be submitted
* Security and usability problems occur

Solution: Use Yup with Formik

Formik has built-in support for Yup.

---

*** 6- The Touched State ***
# Handling Touched Fields and Showing Validation Errors Properly in Formik

## 1. Problem: Validation Errors Show Too Early

### Issue

When the app reloads and the user starts typing in the email field, the password error appears immediately even though the user never interacted with the password field.

This creates a bad user experience.

Example:

* User types email
* Password error appears without touching password

This happens because Formik validates all fields, regardless of user interaction.

---

## 2. Solution Overview

We must:

1. Mark a field as touched when the user leaves it
2. Show error messages only if:

* The field has an error
* AND the field has been touched

Formik provides:

* `setFieldTouched`
* `touched` object

---

## 3. Step 1: Get Required Properties from Formik

Add these Formik props:

-------------------code----------------------
{({
  handleChange,
  handleSubmit,
  setFieldTouched,
  errors,
  touched
}) => (
-------------------code----------------------

Explanation:

| Property        | Purpose                           |
| --------------- | --------------------------------- |
| setFieldTouched | Mark field as touched             |
| touched         | Object that tracks touched fields |
| errors          | Contains validation errors        |

Example touched object:

-------------------code----------------------
{
  email: true,
  password: false
}
-------------------code----------------------

---

## 4. Step 2: Mark Field as Touched Using onBlur

We use the `onBlur` event.

### Email Field

-------------------code----------------------
<AppTextInput
  placeholder="Email"
  onChangeText={handleChange("email")}
  onBlur={() => setFieldTouched("email")}
/>
-------------------code----------------------

Explanation:

When user leaves the field:

-------------------code----------------------
setFieldTouched("email")
-------------------code----------------------

Formik marks email as touched.

---

### Password Field

-------------------code----------------------
<AppTextInput
  placeholder="Password"
  secureTextEntry
  onChangeText={handleChange("password")}
  onBlur={() => setFieldTouched("password")}
/>
-------------------code----------------------

---

## 5. Step 3: Show Error Only If Field is Touched

Formik provides:

-------------------code----------------------

touched.password
-------------------code----------------------

Instead of conditional rendering, create a reusable prop called visible.
